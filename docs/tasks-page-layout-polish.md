# 计划任务页排版优化

日期：2026-09-26

## 问题与目标

原任务列表把名称、周期、项目、状态和下次运行挤在可换行的横排里，信息主次不清；编辑弹窗宽度较窄，任务内容与执行计划混在同一列；左栏“返回工作区”按钮未占满导航宽度。此次只调整前端展示，调度表达式、保存、立即运行、暂停、删除及历史数据契约均不变。

## 实施

- 返回工作区按钮使用 antd `Button block`，与左栏“新建任务”按钮同宽。
- 列表使用 antd `Card`：标题行展示名称、运行状态与启停开关；主体先展示指令摘要，再以三列展示周期、下次触发和项目；历史可展开；立即运行、编辑、删除等分放在卡片底部。元数据按内容区宽度切换为单列，避免左栏较宽时被过早截断。启停和立即运行请求未结束时显示 loading 并阻止重复提交。
- 编辑弹窗加宽至 680px，以 antd `Form` 的 vertical 布局分成“任务内容”和“执行计划”。周期参数在宽窗口下两列显示，窄窗口下单列；语法说明、校验错误和保存失败仍在原位置可见。弹窗正文独立滚动，底部保留唯一一组取消/保存操作。
- 状态文字与分组标题补齐中英文翻译；色彩继续使用主题 token，删除操作使用危险样式。

## 验证

前端 101 个测试文件、1231 个测试通过，TypeScript 检查与 Vite 构建通过。任务页与应用烟测 55 项通过。开 PR 前已清理存量 lint 问题，`pnpm prepr` 全部硬步骤通过。

按仓库约定，界面交由用户手动检查：宽/窄窗口的任务卡片与返回按钮、新建/编辑弹窗的每种周期字段、历史展开、启停与删除确认、保存失败提示，以及中英文和明暗主题。
