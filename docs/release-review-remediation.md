## 修复契约

| 问题 | 修复后的行为 | 回归边界 |
|---|---|---|
| G3 拒绝只拦住第一次写入 | 拒绝范围持续返回 `E_SCOPE_DENIED`，同范围不重复询问；收窄回批准基线放行，真正新增范围再次询问，显式重新批准清除旧拒绝缓存 | 同批、多批、并发写、收窄、新增、重新批准 |
| 包标签吞掉真实需求 | 只剥离完整匹配的包序号与明确角色（builtin、历史 docs-writer、约定中文 reviewer）；未知 kebab/snake 词不再凭形态放行 | `包 A（删除数据库）`、`包 A（delete-db）`、`包 deleteDatabase` 不得吞掉真实需求 |
| 运行回查覆盖新 run | Tab 本地生命周期代数、启动中标记与后端 `run_id` 共同约束回查；关闭后重开同 id、启动窗口、迟到 true/false 均不能覆盖新状态 | 延迟 IPC 与启动/收尾/重开交错 |
| 服务推送全局抑制回查 | 有服务卡时定期拉取完整快照，任一服务日志都不推迟其它服务的状态纠偏；避免重叠请求与迟到快照 | A 持续输出、B 静默退出，首张新卡及最后一张卡移除 |
| `wait` 活日志必须等退出 | 仅传 `match` 时允许运行中命中；显式 `state` 与 `match` 同时传时继续 AND；两者均省略默认 `done` | ready 日志与显式 done 的不同语义 |
| 计划任务连续同状态不能完成 | 每轮登记重置运行态，本轮 `finish` 即完成；`baseline` 只作诊断，不要求本轮状态不同 | 连续 ok、error、skipped，包括无上轮状态 |
| 短命服务 finish 早于 register | 成功入表并登记后才释放 reaper；容量失败仍回收进程与输出任务 | 实际快速退出服务与启动失败清理 |
| 子代理 partial 被登记为失败 | 有成果的 `partial` 归成功终态；分析门 `analysis_done` 仍只接受完整 `<report>` | wait 可承认部分成果，G2 不被部分分析解锁 |
| 完成事件丢失后队列不自动续跑 | 新增 `session_run_snapshot` 返回最近一轮身份与完整终态；仅匹配的 `done` 复用完成 handler 续队，error/cancelled 保持暂停 | 事件与快照同时到达不重复出队；提示与保存告警可回填 |
| 服务停止后最终日志丢失 | 退出/停止事件携带最终 tail，前端收尾及缺席快照保留已知日志 | 自然退出、手动停止；事件丢失时保留已有日志 |

`session_run_snapshot` 为只读 IPC，事件键仍为 29 个。快照在同一锁内读取 `running`、`run_id`、`terminal`，收尾检查点保存完毕后再发布空闲；steer 的检查点不结束当前 run，旧轮收尾不能覆盖新轮。终态只保留进程内最近一轮，应用重启后没有历史终态可回查。

前端启动回执返回前，未知身份的 start 事件不认领运行身份；终态按 run_id 暂存，回执确定身份后只重放匹配的一项。暂存最多 16 个身份，超界后立即通过权威快照补偿，因此较早的多轮迟到事件不会误杀新启动，也不会因缓存淘汰漏掉当前收尾。

1. 批准计划后增加计划外步骤并拒绝，确认后续同范围写入仍被拦；收窄回批准内容后正常继续。
2. 连续排入多条消息，验证正常完成自动出队，取消与错误暂停；快速切 Tab、关闭重开及点击发送时不出现旧运行态回写。
3. 同时启动持续输出与静默服务，停止其中一个，确认状态在回查周期内收敛，停止按钮消失且最后日志保留。
4. 用 `wait` 等待长驻服务 ready 文本，确认进程仍活着时返回；显式追加 `state: done` 则继续等退出。
