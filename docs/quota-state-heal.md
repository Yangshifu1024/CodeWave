# quota.json 启动期自愈

> 2026-09-20 · 给 `~/.codewave/quota.json`（记录「曾经成功取过额度的供应商」）加一条启动期自愈：损坏内容隔离留证、无效记录清掉、形态不可读的重写为可读。需求与逐条决策见 `.codewave/tasks/20260920-125825-quota-state-heal/{requirement.md,plan.md}`。
> 前置批次（本文件自愈的那个状态文件从哪来）：[docs/quota-from-provider-config](./quota-from-provider-config.md)。

## 1. 为什么需要它

`quota.json` 是「**曾经成功过**」这件事的**唯一持久载体**，而它是 401/403/404 两种含义的唯一判据：

| 记录状态 | 额度行 | 用户读到的结论 |
|---|---|---|
| 有记录 | `error` 错误行（带 `!` + 原因 + 重试 + 「上次成功：X 前」） | 「临时失效，可以重试」 |
| 无记录 | `rejected` 灰行 | 「查询被拒（可能非订阅账号）」 |

改动前 `state::load` 遇到损坏只**静默回退默认**（日志一条 warn），文件本身不修；而写盘只在「本批有成功者或有孤儿」时发生。于是坏文件可以长期存在：

- 每次启动都重复告警，永不收敛；
- 全部「曾成功过」事实失效 → 那些家被渲染成「**查询被拒（可能非订阅账号）**」——一个**误导性结论**；
- `last_ok_at` 为空串的残记录则自相矛盾：`has_succeeded` 为真（走 `error` 行）但展示层拿不到时间 → 「曾成功过」在界面上不可见。

## 2. 行为（启动时 `lib.rs` setup 内同步调一次）

`core::quota::state::heal(&data_dir)`，与日志清理 / 崩溃恢复 / 幽灵会话清扫**同类**的一次性维护；小文件同步 IO，不用 `spawn_blocking`。

| 盘上形态 | 处置 | 结果 |
|---|---|---|
| 文件不存在 / 读不到 | 什么都不做 | 不创建、不写盘（保持「无记录 == 文件不存在」不变式） |
| `version` 数值形态（含 `2.0` / `"2"` / 超 `u64`）大于当前 schema | **完全不碰** | 只记日志。降级运行时既不挪走新版数据，也不把未知字段写没 |
| JSON 语法坏 / 顶层非对象（`[]`·`null`·数字）/ `verified` 非数组 | **移动隔离**为 `quota.json.corrupt`，**不重建** `quota.json` | 原字节逐字保留作证据；下次成功刷新自然重建 |
| 元素级类型错（`last_ok_at: null`、`provider_id: 123`、元素非对象） | 逐元素丢弃该条 | **不隔离**——隔离会让同一文件里合法记录的「曾成功过」一起失效（等于把可用供应商说成非订阅账号） |
| `provider_id` trim 后为空 / `last_ok_at` 空串或非法 RFC3339 | 清掉该条 | 删除判据只收窄到「必然不可用」 |
| `version` 形态非法（`"abc"`·`null`）/ `verified: null` | 重写为可读形态（**不删记录**） | 这类形态 `load` 会整文件回退默认——不修就永远每次启动告警、且「曾成功过」全失效 |
| 健康 | 什么都不做 | **不写盘、不记日志**（不 churn mtime） |

**宽容度**：时间戳判定只用 `chrono::DateTime::parse_from_rfc3339` —— `Z`、`+08:00` 等偏移、小数秒**都算合法**。自己写正则或只认 `to_rfc3339_opts(.., true)` 生成的 `...Z` 形态都会误删合法记录。

**版本号本身不触发写盘**：`version` 为合法 `u32` 时原样保留（`version: 0` 也不会被规范化），缺失或非法时才取当前 `VERSION` 并（因 `load` 读不回来而）重写。

## 3. 核心不变式

> `heal` 返回后，`quota.json` **要么不存在**（读不到 / 已被隔离），**要么 `QuotaState::load` 必定成功、且读出的状态等于自愈保留的状态**。

写盘判据即由此而来：`丢过记录` **或** `盘上内容按严格语义读出来 ≠ 保留结果` 才写。为什么这样就够——写盘内容就是保留状态的序列化结果，写完 `load` 必然成功，且下一次自愈必然转 no-op（不会反复写盘）。

这条不变式是**修第三轮才补齐**的：最初实现只在「丢了记录」时写盘，于是 `{"version":"abc"}` 与 `{"verified":null}` 这类「自愈认为健康、`load` 却读不了」的形态永远修不好。为此新增 `HealOutcome.repaired_only`，把「只为修可读性而重写（`dropped == 0`）」与「清了坏记录」分开表达，避免日志读者把 `dropped: 0` 误读成「什么都没做」。

## 4. 隔离备份 `.corrupt`

- 语义**同 `ui-state.json.corrupt`**：只作证据、可被下次隔离覆盖（隔离前先删同名旧备份）、不参与任何判据、不自动清理。**不是** `sessions/index.json.corrupt` 那种「持久不可信信号」（那份会被清理逻辑当判据读）。
- 隔离实现：`fs::rename` → 失败退化 `fs::copy` + `remove_file` → 再失败只 warn 并**保留原文件**（清掉可能留下的不完整副本，维持「`.corrupt` 存在 ⟺ 原文件已被移走」）。
- 隔离后**不重建** `quota.json`：本仓库既有不变式是「没有任何曾成功记录时文件不存在」（`commit` 在无成功者且无孤儿时也不写盘）；重建一个空文件只会让「无记录」多一种等价表示。

## 5. 并发与失败

- 与 `state::commit` **共用同一把进程内互斥**（`lock_io`）：「读—改—写」全程在临界区内，临界区内**只有同步文件 IO、不跨 `.await`**。不共享锁就会出现「自愈读到旧状态 → 刷新落盘 → 自愈用旧快照覆盖」，正是本文件存在的理由（额度静默消失）。
- 写盘一律走既有 `QuotaState::save` → `util::atomic::atomic_write`（tmp + rename，权限保持 `0600`），不留临时文件与 `.bak`。
- 任何失败路径只有 `tracing::warn`，**不 panic / 不 unwrap**：目录只读、磁盘满、隔离失败都退回自愈前行为（`load` 仍回退默认），不影响启动与额度展示。
- 日志只带**结构化摘要**（`serde_json` 的类别 + 行列号），**不回显文件内容**——日志常被用户分享。健康文件**零日志**（只有确有变更才 warn）。

## 6. 非目标

不做备份/恢复 UI 与 `.corrupt` 归档清理策略；不做版本迁移；不自动修复 `provider_id` 拼写或映射到现有供应商；不做重复 id 去重（展示层 `find` 取首条）；不做运行中周期性自愈；不做文件大小上限；不加用户可见提示/toast；不改展示层与 wire 契约（`last_ok_at_of` 的空串过滤保留为运行期防御）。
