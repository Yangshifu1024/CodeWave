# 暗色主题背景误判修复

> 日期：2026-10-11。纯前端缺陷修复。

## 根因与修复

暗色模式下导航、主区域与标题栏仍呈亮色，而文字已经切成浅色，导致界面无法阅读。
antd 的暗色算法默认返回 `colorBgBase = #000`，原 `isDarkBase` 只接受六位十六进制色值，将三位简写判为亮色。
因此主题桥强制写入亮色导航底色和白色主区域底色；代码高亮与 HTML 预览画布也选择了亮色分支。

在 `ui/src/theme/colors.ts` 统一亮度判定，先将三位十六进制简写展开为六位，再沿用原亮度计算。
主题桥和 HTML 预览共同消费该函数。背景仍取 antd 的容器/布局 token，亮色模式保持现有底色。
主题偏好的来源与切换流程不变，见 [主题与强调色契约](./ask-ink-accent-and-composer-cover.md) 和 [侧栏分色设计](./rightbar-visual-batch.md)。

## 回归验证

`theme.bridge.test.tsx` 使用真实 antd ConfigProvider 与算法，覆盖亮色→暗色→亮色的背景、文字和代码高亮同步，以及暗色下打开 HTML 预览的默认画布。
修复前两条用例均失败：主区域实际为 `#FFFFFF` 而非 `#000000`，预览实际为 `light` 而非 `dark`。

修复后 `pnpm --dir ui test`：116 文件、1464 用例全部通过；`pnpm --dir ui build` 与 `pnpm --dir ui run lint` 通过。
首次沙箱运行因 worker 临时文件不可共享而报 ENOENT，改在沙箱外重跑全量后通过。
代码审查覆盖项目要求的七个维度，无阻断问题。

## 手动验收

1. 设置 → 外观 → 暗色：左栏、标题栏、中栏和右栏均为暗底，文字与窗口控制按钮可读。
2. 打开会话和设置页，检查输入框、菜单与代码块文字可读。
3. 亮色→暗色→亮色反复切换，背景与文字同步变化。
4. 选择跟随系统并切换系统亮暗主题，检查同样的同步行为。
5. 暗色模式打开 HTML 预览，默认选深色画布；手动切换浅色/深色仍可用。

按项目约定不做 GUI 自动点验；上述视觉验收由用户手动执行。
