# 目标模式：完整交付与完全访问执行

> 2026-09-26。需求经 grilling 多轮澄清，用户最终授权直接开发，真实项目由用户在本地验收。本方案取代 [goal-mode](./goal-mode.md) 中的目标执行账本和固定文本轮数停机语义；恢复基础参考 [goal-mode-recovery](./goal-mode-recovery.md)。

## 需求基线

用户持有需求文档和技术方案，希望目标模式完成整个项目开发。允许重做实现，不接受以阶段成果、Mock、占位或自勾验收项冒充完成。执行权限至少与完全访问一致，不能因为遗漏程序或目录白名单而停机。

- 澄清只读，建立需求、任务、验收对应关系；必要质量要求与已有失败基线在开工前明确。
- 用户一次批准范围、验收标准及预算；预算显式选择 token/执行时长限额或不设上限。模型不得替用户选择。
- 连续推进里程碑、开发、联调、测试与独立审查。实现细节可调整；不能擅改核心需求、降低标准或无限增加范围。
- 局部受阻先推进独立工作；有限重试后无法继续才暂停并给出恢复条件。
- 主代理、子代理与压缩合计预算；跨续跑累计。到限停止新工作，允许已发请求的在途用量。预算不是供应商严格扣费封顶。
- 暂停与异常退出保留合同、进度和验证记录；重启由用户显式续跑。普通补充消息不自动续跑。
- 同目录默认单一目标执行者；外部修改使相关证据失效，不能覆盖用户修改。
- 机器验收关联真实工具调用与文件内容快照；独立 reviewer 重新核对原文；人工项进入待验收，由用户确认或反馈后继续修复。
- 停止先进入「正在停止」，待子代理与目标自建服务回收后才显示「已暂停」。预览服务可以在验收阶段保留；不停止用户已有服务。

## 技术方案与实施清单

保留现有目标入口及会话持久化，替换执行策略；不引入框架依赖或另起云端/守护服务。

1. 权限：目标执行期复用 FullAccess 的命令围栏策略，移除目标账本、简单命令解析和额外高危拦截；恢复 HTTP/MCP。澄清与暂停阶段不提供写入授权。保留其它权限档原有行为。
2. 合同：`GoalState.delivery` 保存用户预算、累计用量、需求文档、基线、真实验证记录和逐项证据；字段带 serde default。历史 ledger 仅保留数据，不再产生授权语义。
3. 验收：在实际工具执行前后计算源文件指纹，仅前后相同且工具成功才能作为验证；provider call id 关联证据。验收时重算指纹，防过期、伪造或失败结果。完成调用独占工具批次，子代理结束后才能收尾。
4. 审查：目标执行期 reviewer/code-reviewer 的独立报告明确通过/不通过；仅通过报告能满足审查门。人工项不允许模型勾选。空验收清单不能完成。
5. 生命周期：增加 stopping、awaiting_acceptance，统一错误、取消和耗尽路径。运行与服务退出的真实状态决定 UI 状态；项目并发写入在 core 拦截。
6. 前端：预算编辑、用量、文档与证据展示，人工验收通过/反馈，暂停续跑；全部复用 antd。事件仍使用 `goal:update`，不改事件键名。
7. 验证：后端完整测试、前端测试/构建/lint、代码审查，修复发现的问题；真实 GUI 与需求项目由用户本地验收。

## 证据边界

文件快照用于判断证据是否对应当前成果，不是操作系统沙箱。完全访问下程序的内部行为仍按完全访问的既有能力执行。默认排除 `.git`、`.codewave`、依赖目录与构建缓存；显式列出的需求文档仍计算内容。工具成功与独立审查是交付证据，不构成软件绝对无缺陷的承诺。

机器验收命令及工作目录在批准时固化，任意成功命令不能替代批准的检查。需求原件单独保存到会话的 `.goal.sources` 目录（包括二进制原件），独立审查读取原始快照；开发过程中仍可正常更新项目中的方案文档。源文件不遵循 `.ignore` 隐藏规则，受 Git 跟踪的输出目录文件仍纳入指纹。原件随会话级联清理。

本地桌面进程在托盘驻留时可以继续执行；真正退出或机器关闭后依赖持久化恢复，不承诺进程退出后仍运行。

## 手动验证清单

1. 打开项目，切换目标模式，提供需求文档与技术方案路径；确认澄清期不修改文件。
2. 检查目标验收项与人工标记，选择限额预算或不设上限，再批准。预算未选时不能开始。
3. 执行正常开发命令、复合命令及配置好的网络/MCP 工具；确认不会出现目标账本未列程序/目录的拒绝。
4. 连续完成多个里程碑，不重复要求输入“继续”；真实失败应说明问题、修复并重试。
5. 检查 token/时间用量；小预算耗尽后不能启动新工作，增加预算后可继续，已用额度不清零。
6. 执行中点击停止，确认先显示正在停止；子代理及自建服务结束后显示已暂停。其它会话或用户自建服务不被停止。
7. 暂停后发补充信息，确认不会自行恢复；点击继续才运行。重启应用后目标、预算与进度能恢复。
8. 同项目开另一会话尝试写入，确认与活动目标互斥；手动修改源文件后，旧验收结果不能直接完成目标。
9. 故意只勾选验收项或引用失败/不存在的调用，确认无法完成；测试通过后再改代码，确认要求重新验证。
10. 独立审查检查原始文档；存在问题时修复再审。机器验收完成后，人工项进入待你验收；反馈问题后仍沿原目标修复。
11. 人工通过后确认状态、历史与重启展示一致；交付报告包含逐项验收与必要文档。
