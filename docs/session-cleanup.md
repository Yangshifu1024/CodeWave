# 会话保留期与清理（实施方案）

> 2026-09-19 · 需求：在设置中增加会话清理配置——默认不清理；可选 1/3/7/14/30 天；按所选天数清理更早的会话。
> 本文件先落盘需求与方案（动代码之前）；实施结果与验证记录见 §11。
> 2026-09-19 第 2 版补充：新增 5 条决策（§3 第 24–28 条）与 8 条边界事实（§4 末尾），来自一轮针对本方案的专门追问与代码核对。

## 1. 需求原文

在设置中增加会话清理配置：

1. 默认不清理
2. 用户可选择 1/3/7/14/30 天
3. 按照用户选择，清理对应天数以前的会话

## 2. 目标与非目标

**目标**：让本地会话数据（历史、边车、会话日志、计划文件）有一个按保留期自动收敛的机制，默认关闭、开启后行为可预期、执行前看得见会删什么。背景是 CodeWave 为本地优先产品，会话数据只增不减，长期使用后磁盘持续膨胀，而现有唯一手段是左栏逐条删除。

**本次不做**：回收站/撤销删除；固定会话豁免；自定义天数输入；按项目分别设置保留期；按自然日计算；删除用户项目文件与任务目录文档；清理全局诊断日志与其他非会话数据；新增前端事件；压缩归档旧会话；改动会话列表排序与行内时间口径。

## 3. 决策记录（与用户逐条确认）

1. 保留期档位固定为 不清理 / 1 / 3 / 7 / 14 / 30 天，不做自定义天数输入；配置为**全局一份**，不按项目分别设置。
2. "更早"的判定基准 = 最近活动时间 = `max(updated_at, last_opened_at)`；按**精确时长**（当前时间 − N×24 小时）判定，不按自然日。
3. 会话元数据新增"最近打开时间"字段（可缺省、旧数据兼容），在**加载会话时刷新**；会话列表排序与行内时间显示保持现状（仍用 `updated_at`），因此点开会话不会被顶到列表最前。
4. 时间戳无法解析的会话**不删**并记告警；未来时间戳不会被删。
5. 正在运行的会话一律跳过（同时查索引标记与进程内运行集合）；删除后清运行态，避免在途写入把会话"复活"。
6. 清理范围：会话索引行 + 历史文件 + 待办/产物边车 + 子代理过程历史 + **工具结果原样 sidecar 目录（`sessions/<id>.toolres/`，[session-restore-fidelity](./session-restore-fidelity.md)）** + **图片外置 blob 目录（`sessions/<id>.imgblob/`，子代理为 `sessions/<父>__<sub>.imgblob/`，[session-history-limits](./session-history-limits.md)）** + **该会话的日志文件** + **该会话产生的计划文件**；临时会话（未绑项目）同样纳入。
7. 会话日志位置分叉：项目会话在项目数据目录的 `logs/`，临时会话在全局数据目录的 `logs/`；项目已删除或文件不存在时视为成功。
8. 一并清理**索引之外的残留**（超出索引条数上限被挤出、列表已看不到的会话文件，含 `sessions/<id>.toolres/` 与 `sessions/<id>.imgblob/` 目录，但子代理 blob 目录 `sessions/<父>__<sub>.imgblob/` 显式跳过），按文件时间判定。
9. 绝不删边车中登记的用户项目文件；任务目录里由写入工具生成的文档（需求/方案/审查/报告）本次不连带删除。
10. 计划文件做归属登记：落盘时登记进会话产物边车并加"种类"标记；右栏「文件」面板的数据源不再返回计划文件（现状本就不显示，属保持现状）。
11. 触发时机：应用启动时一次（**异步**、不阻塞窗口显示）+ 设置页保存时一次 + 手动「立即清理」按钮；另有只读的"上次清理"信息可读取。
12. 保存时若确实会删到会话，先弹确认框（删除条数 + 前几条会话标题）；**取消 = 仅本次跳过清理**，配置照常保存，下次启动仍按新保留期清理（取消按钮写明这一点）。
13. 手动「立即清理」用**已保存的**保留期；有未保存改动时按钮禁用并提示先保存。
14. 设置页显示"上次清理：时间 + 删除条数"，**存后端**（重启后仍在），启动时的自动清理也计入；自动清理确有删除时给一条轻提示。
15. 清理后前端刷新会话列表，被删会话若开在 Tab 里则关闭其 Tab（顺序：丢弃 Tab 内容 → 清运行态 → 关 Tab → 刷新列表）。
16. 不做回收站；不做固定会话豁免；不新增前端事件（走命令返回值传递被删会话 id 列表）。
17. 删除顺序：先删文件、**最后一次性写索引**；某条会话文件删除失败则保留其索引行，下次清理再试；单条失败不中断整批，失败与条数都记日志。
18. 设置项落在设置页「工作区与智能体」页，走"点页级保存后生效"的普通字段路径（不是即时生效字段）。
19. 清理记录（上次清理时间、删除条数、失败条数）写到全局数据目录下的一个小 JSON 文件。
20. 启动清理先**同步挑出候选**、再异步删除，避免与前端恢复 Tab 的顺序不确定导致结果随机。
21. 界面改动不做自动点验，交付分步手动验证清单。
22. 新增设置项必须同步设置注册表、页字段归属、中英文案，否则既有契约测试直接变红。
23. 新增配置字段、会话元数据字段、边车字段一律带默认值，旧配置、旧索引、旧边车都能直接加载，不做迁移。
24. "最近打开时间"落盘**节流**：同一会话 10 分钟内不重复写索引；精度损失对"天"级判定无影响，避免每打开一个会话就重写整份索引。
25. 保留期为"不清理"时，「立即清理」按钮**禁用**并注明"先选择保留期"。
26. 清理执行期间按钮**转圈**；完成后提示"已清理 N 个会话，关闭 M 个标签页"。
27. 离开拦截里的"保存并离开"若触发清理，**同样弹确认框**；用户选"暂不清理"时配置照常保存、离开照常进行。
28. 本次一并补上启动恢复的**"列表不可信"守卫**：会话列表加载失败时不剔除 Tab，避免一次 IPC 抖动清空工作现场。

## 4. 现状事实（调研结论）

- 会话索引与历史统一存在全局数据目录 `~/.codewave`：`sessions/index.json`（索引）、`histories/<id>/`（历史：**分段 append-only JSONL**，`0001.jsonl…` + 水位边车 `.segmeta.json`；[session-history-storage](./session-history-storage.md)）、旧格式遗留 `histories/<id>.json.gz`（读兼容、不自动删，可由设置页的「清理旧格式历史」入口回收）、`sessions/<id>.todos.json` 与 `sessions/<id>.artifacts.json`（边车）、`histories/subs/<id>/`（子代理过程历史，同为段式）、`sessions/<id>.toolres/`（工具结果原样 sidecar）与 `sessions/<id>.imgblob/`（图片外置 blob，子代理为 `sessions/<父>__<sub>.imgblob/`；[session-history-limits](./session-history-limits.md)）。
- `SessionMeta`（`src-tauri/src/core/sessions/store.rs`）字段：`id` / `title` / `workspace` / `model_id` / `created_at` / `updated_at` / `message_count` / `project_id` / `roots` / `running` / `interrupted`；时间戳为 RFC3339 字符串；`created_at` 在 upsert 时保留首见值，`updated_at` 只在会话落盘检查点时刷新，没有"最近打开时间"。
- 现有唯一会话删除入口 `SessionStore::remove`：删索引行（持索引锁）+ 历史 + 两个边车 + 子代理历史目录；**不删**会话日志，**不删**计划文件；文件删除失败静默忽略。
- 索引有条数上限 2000，超出按 `updated_at` 倒序截断，被截断的会话文件仍留在磁盘且没有重新入索引的生产路径（"索引外残留"由此产生）。
- 会话日志：项目会话在项目数据目录 `logs/<id>.log`，临时会话在全局数据目录 `logs/<id>.log`；除全局滚动日志的 14 天清理外没有任何保留期，也没有按会话删除日志的函数。
- 计划文件：每次 ask 落盘 `<工作区根>/.codewave/tasks/plan-<时间戳>-<随机4位>.md`（项目会话 = 项目主目录，临时会话 = 全局数据目录下再套一层 `.codewave`）；文件名不含会话 id，当前**没有**归属登记，也不在产物边车里。
- 产物边车被右栏「文件」面板全量渲染，没有过滤字段；写入登记点只有创建/编辑工具两处（路径归一 + 任务运行态跳过 + 失败只记告警三条纪律）。
- 既有"保留期清理"先例：全局滚动日志 14 天（启动时同步执行、失败只记告警、纯函数可单测）、统计日聚合 90 天、命令输出临时文件 24 小时（惰性节流）。
- 配置：`~/.codewave/config.json`，`ConfigState`（`src-tauri/src/core/config.rs`），容器级 `#[serde(default)]`；保存走 `save_config`（整份覆盖 + 掩码回填 + 若干即时副作用）。
- 设置页：注册表 `ui/src/features/panels/settingsRegistry.ts`（页集合/设置项/页字段归属/宽度档/豁免清单）+ 手写页体 `SettingsPage.tsx`；共 8 页 3 组，其中「工作区与智能体」页对应 `agent`；新增设置项不动注册表/页字段/文案必被契约测试判红。事件面锁 29 键，本次不新增事件。
- 启动恢复 Tab 本来就会校验会话是否存在于会话列表，已删会话的 Tab 被**静默剔除**（`ui/src/stores/sessions.ts` 的 `restoreTabs`）——清理不需要为此新增机制；但会话列表加载失败被容错成空数组时没有任何守卫，会把全部 Tab 剔除（本次补，见 §3 第 28 条）。
- 计划卡片对计划文件的引用只活在**运行态事件**里、不落进聊天历史，所以删除计划文件不会造成历史消息里的死链；只有"运行态卡片仍在、文件已被清理"这一极小概率场景会走到通用告警，本次补一条友好文案。
- 临时会话的计划文件确认是**双层路径** `~/.codewave/.codewave/tasks/plan-*.md`（工作区根已是全局数据目录，又拼了一层 `.codewave`）；项目会话是单层 `<主目录>/.codewave/tasks/`。
- 清理"索引外残留"时**必须排除 `sub_`/`task_` 前缀**：子代理过程历史与计划任务的 id 本来就不在会话索引里，按"id 不在索引"判定会误删它们（启动时的既有清扫处理的正是这些前缀）。
- `load_session` 目前是纯读（0 次磁盘写）；新增"最近打开时间"后每次加载会变成 1 次全量索引重写，故需节流（§3 第 24 条）。
- 保存配置全仓只有**一个**生产调用点；设置页的保存函数返回布尔值被"离开拦截"依赖，扩展时必须保持布尔返回，清理结果另存状态。
- 清理删除后必须把该会话的运行时对象从内存注册表移除，否则迟到的检查点写入会把索引行"复活"（既有单会话删除已这么做）。
- 删除顺序自带自愈性：先删文件、最后写索引；若最后写索引失败，索引行仍在且时间不变，下次清理会再次命中，重删文件（已不在视为成功）并再次尝试删除索引行。

## 6. 接口与数据变更

- 配置：`sessions.retention_days`（`null` = 不清理；`1/3/7/14/30`）。
- 会话元数据：`last_opened_at`（可缺省，RFC3339 字符串）。
- 边车条目：`kind`（缺省普通产物；计划文件为 plan）。
- 保存配置：由"无返回"变为"可返回本次清理结果（被删会话 id 列表）"，并新增可选参数"跳过清理"；其他调用点不传即维持原行为。
- 新命令：预览清理（按给定天数返回将删条数 + 前几条标题）、执行清理、读取上次清理状态。
- 新状态文件：上次清理记录（全局数据目录内）。

## 7. 执行顺序

1. 本文档落盘 + `docs/0-README.md` 登记（动代码前）。
2. 配置字段 → 会话元数据字段 → 清理核心 → 清理记录与启动接入 → 命令与保存链路 → 计划文件登记。
3. 前端契约 → 设置页界面 → 前端清理收尾。
4. 测试与手动验证清单 → 本文档追加实施结果。

## 8. 风险与回滚

- **误删风险（最高）**：默认不清理；解析失败不删；只删 CodeWave 托管数据；计划文件仅删已登记归属的；删除前有预览与二次确认；启动那次无法询问，给轻提示与日志。
- **启动竞态**：先同步挑候选，避免"先恢复 Tab 就刷成刚刚活动"造成结果随机。
- **持久化兼容**：新字段全部带默认值，不做迁移。
- **路径改签名**：保存配置签名变化由编译器兜住漏改的调用点。
- **契约测试**：新增设置项必须同步注册表/页字段/文案（保护而非风险）；不新增前端事件，避免动事件契约。
- **回滚**：功能默认关闭（不清理）；代码集中在少数文件，可整体回退提交；已删除数据不可恢复，故默认值必须保持"不清理"。

- 前端：`pnpm --dir ui test` 与 `pnpm --dir ui build` 全绿，新增用例覆盖：设置项渲染与档位选择、保存前确认框与取消路径、手动清理按钮禁用条件、被删会话 Tab 关闭与列表刷新、注册表与文案契约。
- 界面：不做 GUI 自动点验，交付分步手动验证清单（默认不清理时不动数据、选 1 天保存后的确认框内容、取消后数据不动、手动清理、Tab 自动关闭、右栏文件面板不受影响）。

## 10. 已知遗留

- 任务目录下的四份流程文档不随会话清理，长期仍会残留。
- 本次改动之前生成的计划文件没有归属登记，不会被清理带走。
- 清理只承诺"删除了 N 个会话"，不承诺释放的具体磁盘字节数。
- "索引行保留但历史文件已删"的半删状态（最后写索引失败时）在打开会话时会透出底层文件错误，未被专门处理，依赖下一次清理自愈。
- 计划文件被清理后，极小概率下运行态里的旧卡片点开会走到通用告警（仅补文案，不做跳转兜底）。

## 11. 实施结果与验证记录

### 11.4 界面手动验证清单

前置：仓库根执行 `pnpm tauri dev`（确认没有打包版实例在跑）；建议先备份 `~/.codewave/sessions/index.json` 便于核对删除效果。

1. 设置 → 左导航「工作区与智能体」：看到三行——保留期下拉（显示**不清理**）、「立即清理」（**灰掉**，右侧写"先选择保留期"）、「上次清理」（"还没有清理记录"或上次记录）。
2. 展开下拉：选项恰为 不清理 / 1 天 / 3 天 / 7 天 / 14 天 / 30 天；左栏出现未保存圆点。
3. 选「30 天」但不保存：「立即清理」点不动，提示变成"有未保存的改动，先保存"；选回「不清理」后圆点消失。
4. 制造数据：正常用出 2–3 个会话（临时会话即可），让其中一个的"最近活动"明显早于保留期（可改系统时间验证）。
5. 选「1 天」→ 保存：若确实有会删的会话，弹确认框（写明不可恢复 + 前几条标题）→ 点「清理」：配置落盘，提示"已保存"与"已清理 N 个会话，关闭 M 个标签页"；被删会话的 Tab 自动关闭，左栏列表刷新。
6. 重复第 5 步但点「暂不清理（下次启动仍会清理）」：配置照常保存、提示写明本次不清理；核对 `~/.codewave/sessions/` 下文件仍在。
7. 保留期已保存为「1 天」时点「立即清理」：弹确认框 → 取消无变化；→ 清理则提示条数与关闭 Tab 数，「上次清理」行立即更新。
8. 让预览为 0（所有会话都刚用过）时点「立即清理」：只闪一条"没有需要清理的会话"，不弹确认框。
9. 离开拦截联动：改保留期为「1 天」不保存，点「返回工作区」→ 三选里点「保存并离开」→ 应先弹清理确认框；点「暂不清理」后设置页照常关闭。
10. 重启应用：启动时静默按保留期清理一次；有删除时给一条轻提示；重新打开设置，「上次清理」显示本次启动的时间与条数（同一次清理不会重复提示）。
11. 回归：右栏「文件」面板不含计划文件、内容正常；会话列表排序与行内时间仍按"最近更新"，点开会话不会被顶到最前。

### 11.5 已知遗留（实施后更新）

- 任务目录下的四份流程文档不随会话清理，长期仍会残留。
- 本次改动之前生成的计划文件没有归属登记，不随会话清理。
- 清理只承诺"删除了 N 个会话"，不承诺释放的具体磁盘字节数。
- **索引外的孤儿会话日志**（`logs/<id>.log`）不在清理范围：它与全局滚动日志同目录，按文件名形状判定的误删风险大于收益。
- **左栏手动删除会话与清理口径不一致**：手动删除不会删该会话的日志与计划文件（既有行为，本批未统一）。
- **索引损坏后的保守停机**：一旦留下 `sessions/index.json.corrupt`，"索引外残留清理"会一直停摆（宁可不删也不误删），需要人工删除该文件才恢复；建议后续加一个显式解除入口。
- "索引行保留但历史文件已删"的半删状态（最后写索引失败时）打开会话会透出底层文件错误，依赖下一次清理自愈。
- 既有邻近缺口（本批未修）：启动清扫 `purge_non_session_entries` 按索引里的编号直接拼路径删除，未过编号白名单校验。
