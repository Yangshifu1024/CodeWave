# MCP 设置页排版与全屏顶栏分界修复

2026-09-25。用户在 0.8.0 验收时发现 MCP 设置页内容横向铺满、状态列错行，且设置页左栏与顶栏灰白分界不齐。

## 原因与修复

- `McpStatusTable` 渲染六列，样式却只有三列网格；后半列被排到下一行。现按名称、来源、状态、工具数、PID、操作六列排版。
- 参数和键值编辑器缺少 `.mcp-table-row` 的横向布局，输入框与删除按钮竖排。现统一成紧凑行。MCP 页体保留阅读宽度并靠左放置。
- 作用域改成「用户级／项目级」页签；路径与连接说明移入提示。「服务器列表」展示配置中的服务器，提供新建与刷新；新增和编辑使用弹框，保存成功后关闭，保存失败保留输入，取消恢复已保存内容。列表不显示环境变量值。
- 状态用语义色标识：已连接为绿、连接中和资源淘汰为橙、错误为红、未连接为灰。断开会回收 MCP 连接，清除 PID、工具数与运行状态；启动中的迟到连接也不会再次变成已连接。
- 全屏设置／任务页左栏使用 `fullscreenNavWidth(windowWidth)`，顶栏左段仍跟随工作区的可拖拽 `navWidth`。现打开任一全屏页时顶栏也使用全屏宽度，且取消这一状态下单侧 0.2s 宽度动画；左右导航统一 `border-box`。
- 进入设置后，顶栏标题固定为「设置」，不再显示会话标题、项目目录、分支或工作区侧栏按钮。Windows 控制条由 decoration 插件注入；补齐其外部样式的 `style-src-elem` CSP 来源，并把插件层级提到设置覆盖层之上。

## 验证

- 前端完整测试：100 文件、1217 用例通过。
- `pnpm --dir ui build`：通过。
- `pnpm --dir ui run lint`：0 error，1 条 `Composer.tsx` 存量 warning。
- 顶栏测试覆盖工作区左栏拖宽及折叠时，设置／任务页顶栏左段仍跟随全屏页导航宽度。
- MCP manager 定向测试：18 项通过；`cargo fmt --check` 通过。Rust 全量测试在当前沙箱有临时目录访问和进程树前提失败，需要在常规本机环境复跑。
- 设置标题与 decoration 修复后，标题栏及应用冒烟定向测试 46 项通过，前端类型检查和构建通过。

## 手动点验

1. 工作区左栏拖到最宽及最窄，分别打开设置页和任务页；顶栏灰白分界与左导航右边界对齐。
2. 折叠工作区左栏后打开两页，最大化、还原、缩窄窗口并切换页面；分界无短暂错位。
3. MCP 页在宽窗口和窄窗口检查六列状态位于同一行；参数、环境变量、请求头的输入框与删除按钮位于同一行，不裁切内容。
4. 切换暗色主题并检查布局；编辑配置、保存、测试连接仍正常。
5. MCP 页内容左对齐，服务器列表标题右侧有「新建」和刷新；无服务器时仍可新建。各状态的颜色、工具数与 PID 对应实际连接。
6. 对 stdio MCP 点「断开」：进程退出、PID 清空、工具数变为横线，状态变灰；再点「重连」能恢复。连接中立即断开后也不应自行恢复。
7. 新建、编辑和删除在弹框内进行。保存成功后弹框关闭并更新列表；取消不落盘；校验失败时保留输入。分别检查用户级和项目级、stdio 和 HTTP 配置。
8. 故意放入无法解析的 mcp.json 时，原始内容可在弹框中修复；新建入口不会覆盖原文。
9. 进入设置后，顶栏只显示「设置」；最小化、最大化、关闭按钮仍在右上角可见可点。返回工作区后，会话标题和项目胶囊恢复。

界面改动按仓库约定由用户手动 GUI 验证。

## 后续调整：服务器卡片与工具说明（2026-09-25）

上述六列表格是历史实现。本次按设置页通用的 `SettingsSection` 与 Ant Design `Card` 改为响应式卡片：服务器名称与状态位于标题，作用域、工具数和 PID 放在次要信息区，模型可用工具以名称和简短说明列在卡片中，编辑配置、断开、重连位于卡片底部。工具说明在当前宽度实际截断时显示可聚焦的问号按钮，用 Tooltip 查看全文；无说明、未连接、已连接但无工具、旧载荷缺少工具详情分别显示明确的占位文案。错误详情保持可展开。

后端 `mcp_status` 与 `mcp:status` 共用载荷新增可选的 `tool_details`，只从已连接服务器经过过滤的工具列表生成，不传入参 schema 或未启用工具，展示时去掉模型侧 `[server]` 前缀。前端使用当前作用域与服务器名匹配状态，避免同名的用户级、项目级服务器串场；非当前会话生效的配置卡片禁用断开与重连，防止后端按名称操作到另一作用域的同名服务器。刷新仅重读状态，不主动重连。

手动验收：在宽窄窗口、浅深色主题下查看卡片网格和底部操作；连接含短说明、长说明、无说明的 MCP 服务器，确认只有长说明截断时出现问号，鼠标悬停与键盘聚焦均可读全文；分别切换用户级与项目级同名服务器，确认状态与工具不混用；检查未连接、连接中、错误、资源淘汰及工具过滤后的展示。

## 后续调整：MCP 编辑弹框（2026-09-25）

编辑弹框沿用设置页的共享字号、字段密度和 Ant Design 控件。基本信息区明确标注服务器名称与传输方式；连接配置区根据 stdio / HTTP 显示命令、参数、环境变量或 URL、请求头，并把「测试」放在区标题旁。键值行采用响应式双列，窄窗口下键和值上下排列；长值输入框随内容软换行增长，最多显示六行。服务器删除入口移到表单末尾，确认时使用危险色主按钮，与保存操作分开。

环境变量和请求头中名称含常见凭证标记的值默认遮罩，可通过按钮临时显隐。遮罩只作用于展示，不改动草稿或落盘值；新增敏感变量仍可连续输入，失焦后遮罩。增删行会重置显隐状态，避免同名下一行继承被删除行的明文显示。无法解析的原始 JSON 修复入口继续保留。

验证：MCP 弹框、键值表、共享设置样式定向测试共 42 项通过；前端类型检查、改动文件 ESLint 和 Vite 构建通过。全量前端测试 1218 项通过、3 项失败，失败均在未改动的 `scrollAnchor.test.ts`，与本次 MCP 弹框改动无关。

手动点验：在宽窄窗口与浅深色主题下新建、编辑 stdio/HTTP 服务器；检查名称、传输方式、连接字段标签及对齐，输入很长的变量值或请求头值；新增两个同名密钥行，显示第一条后删除它，确认剩余值仍隐藏；确认测试、删除、取消和保存的作用范围及保存后重连行为。

用户复查时指出底部删除入口独占一行，和取消、保存形成两层操作并留下过多空白。后续把删除改为弹框底栏左侧的描边危险按钮，取消与保存仍在右侧。删除使用按钮旁的 Ant Design Popconfirm，确认按钮为危险色；确认后从已保存配置移除该服务器并保存，不会顺带提交弹框里尚未保存的字段改动，取消则保留草稿。

断开和重连按钮现在按会话、作用域及服务器跟踪进行中操作：被点击的按钮显示 loading，同卡片的两个连接操作均暂时禁用，请求和状态快照刷新完成后恢复。进行中状态保存在 UI store，设置页关闭重开也不会重复发起同一操作；失败会释放锁并刷新状态。状态快照按请求序号只接受最新结果，避免较早发起的刷新覆盖连接操作后的状态。定向测试覆盖两种操作期间的 loading、互斥、重复点击、失败重试、页面重开及快照先后顺序。

卡片标题行现在从左到右显示服务器名称、居中的作用域／工具数／PID、连接状态；正文直接进入工具列表。卡片较窄时，这组元信息仍留在标题区域内，换到标题的第二行居中，避免挤压服务器名称与状态。
